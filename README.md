# Topasia Excel 物流工作台 · Railway 版本（2026-10-01）

这份版本以 Excel 模式为首页，保留报价、基础信息、车队统计和待办列表。旧“出口送柜”和“财务”页面已移除入口，旧路径会转到 Excel 模式；旧数据库资料不会被删除。

## 管理员权限

- 管理员账号固定为 **admin**，首次密码通过 Railway 的 `ADMIN_PASSWORD` 设置。
- 登录后，打开导航中的 **全部业务数据**：查看所有账号已保存的 RUNNING、完成、退关业务。可以按账号、截关月份、订舱号、柜号查询并导出当前结果。该汇总页只查看和导出，不会修改同事资料。
- 管理员的 **车队统计**汇总全部账号已保存的 Excel 数据；普通账号统计自己的数据。按送柜月份、车队和卡车类型分类，退关货柜不计入。
- 管理员可以查看全部账号的报价；基础信息和待办仍沿用共享资料。
- 打开 **账号管理**：批准注册申请，或点击同事账号旁的 **重设密码**，输入并确认新密码。密码至少 12 个字符，可以选择显示密码。无需同事的旧密码。
- 重设密码后，同事原有登录会失效，需使用新密码重新登录，订单和报价不受影响。操作记录保存管理员、目标账号及时间，不记录密码。
- 管理员自己的密码在 **账号设置**中修改，需要输入当前密码。已有 admin 密码不会被后续部署的 `ADMIN_PASSWORD` 覆盖。
- 普通账号不能使用管理员接口查看全部业务或重设其他账号密码。

## 本次包含的 Excel 功能

- 拖入或选择 Booking PDF 新增订单，识别订舱号、船司、目的港、柜量、柜型、品名、码头、船名和 Pick up depot。
- PDF 在浏览器中读取，不上传或保存原始 PDF。扫描图片型 PDF 暂不支持 OCR，识别后需核对内容。
- 柜量有几柜就生成几行；新增时可以逐柜填写不同工厂地址、送柜时间、车队及卡车类型，也能套用相同安排。
- 卡车类型：SIDE LOADER、SIDE LOADER WAITING、WAITING FINISH、POTONG TRAILER。
- 堆场作为后台 Booking 资料保存，不占用 Excel 栏目。未识别到堆场会提醒向船公司申请，订舱号旁的“堆场”可补充；ROT 导出自动带入堆场，没有填写时先补充再导出。
- ROT 标准 Excel、PDF 及车队模板，邮件草稿和基础信息邮箱。邮件使用 Foxmail／Outlook 等客户端，不由网站自动发送。
- 完成和退关按截关月份归档；假期、待办、截关前 72 小时未进港、截关前 5 天未填写柜号提醒。
- 栏目逐层筛选、查询、“取消全部筛选”，基础颜色、行高、列宽、字体调整，拖动冻结列。
- A、B、C 等列字母独立一排，标题滚动时固定；表格缩放 50%–200%，缩小 −、比例、放大 ＋、恢复 100%。
- Excel 修改后需点击 **保存**。同事尚未保存的修改不会显示在管理员汇总页。

## 更新现有 Railway 服务

1. 解压 ZIP，把 `railway-topasia` 文件夹里的内容更新到原 GitHub 仓库根目录。`Dockerfile`、`package.json`、`app`、`drizzle` 和 `public` 必须在同一层。把整个 `app` 文件夹和本版 `drizzle` 文件夹一起更新，保留原有数据库迁移文件；不要只更新首页。
2. 保持现有 Railway 服务、环境及 `/data` Volume。**不要删除 Volume，也不要重新创建数据库。**
3. 检查服务 **Variables**：

   | 名称 | 值 |
   | --- | --- |
   | `ADMIN_PASSWORD` | 初次建立 admin 的密码，至少 12 个字符 |
   | `SESSION_SECRET` | 至少 32 个字符的随机字符串；已部署服务保持原值 |
   | `SQLITE_PATH` | `/data/topasia.sqlite` |

   密码和密钥只填写在 Railway Variables，不写入 GitHub。`PORT` 使用 Railway 提供的值。
4. 确认同一个服务、同一个环境挂载 Volume，挂载路径为 `/data`。没有 Volume 或数据库路径不在 Volume 内时，服务会拒绝读写，避免更新丢失账号及订单。
5. 推送文件后让 Railway 重新部署。数据库会自动执行本版迁移，新增登录失效标记和管理员操作日志；保留旧账号及资料。
6. 用 admin 登录。若同事已注册，账号管理里可直接批准或重设密码。若已有名为 admin 的普通账号，首次升级管理员时 `ADMIN_PASSWORD` 必须与该账号当前密码一致。

## 第一次部署

把 `railway-topasia` 文件夹的内容放到 GitHub 仓库根目录，在 Railway 选择 **Deploy from GitHub repo**。配置上面的 Variables 和 `/data` Volume，然后在 **Settings → Networking** 生成域名。其他同事可通过注册页申请账号，无需邀请码，批准后登录。

## 数据说明

- 新注册账号的 Excel 表格为空，不复制其他人的测试业务。旧 Railway 已保存的表格和账号继续保留。
- Sites 和 Railway 是两个独立数据库；**Sites 的数据不会自动转入 Railway**。这份源码不含实际客户业务、登录密码、会话密钥或数据库文件。
- 请使用一个 Railway 服务实例及一个 Volume；这份 SQLite 版本未配置多实例共享数据库。
- 后台堆场资料会跟随整票完成／退关保留。旧记录未导入堆场时，可通过“堆场”补充。
- 2026 年雪兰莪假期表沿用当前测试版；其他年份需更新假期表。
